# Инструкции для проекта «Приложение» (Mandala / Mandal-Art)

**Язык и стиль.** Отвечать по-русски, коротко: что сделано и что дальше. Без планов, технических записок и «ТЗ-отчётов», если их не просили. Блокирующие вопросы — по одному, остальное решать самому и говорить, что решил.

**Работа.** Продолжать существующий проект (STATE-SHORT.md + исходники из zip), не начинать с нуля, не удалять механики, анимации, дизайн. Сначала собрать и показать результат (один HTML-файл), потом объяснять. Работать тонкими срезами: сделал → тесты (node tests/*.cjs по очереди, не параллельно; общий порт) → скриншоты → следующий. Измерять до оптимизации.

**Честность.** Не заявлять непроверенное. В песочнице нельзя проверить: реальные платежи Telegram Stars, реальный телефон и скорость на слабых устройствах, GPU-генерацию 3D (TRELLIS/Hunyuan3D). Так и писать.

**Запреты.**
- фиктивные платежи, мёртвые кнопки, заглушки;
- токены и секреты в клиентском JS;
- USDT / TON / карты как способ оплаты цифровых товаров внутри Mini App — только Telegram Stars (XTR); автоконвертацию Stars→USDT не обещать;
- эмодзи вместо иконок (иконки по теме: Warhammer / One Piece / Scrooge);
- выдавать плоскую картинку за готовую 3D-модель: подписывать честно («объём из картинки» / «3D-модель GLB» / «оригинальная 3D-модель»).

**Права.** Персонажи франшиз (Warhammer 40K, One Piece, Скрудж / Дональд Дак и семья) — только изображения, которые прислал пользователь; в каталоге и figures.json флаг `rights: pending`; публичная сборка (`build.py --public`) их исключает. Самому не рисовать и не моделировать кодом персонажей франшиз. Оригинальные предметы (кристалл, штурвал, монеты, череп-дрон) — можно.

**Сборка и отдача.** `python3 build.py` → `dist/mandal-art.html`; копию отдавать пользователю; в конце каждого этапа обновлять STATE.md. Ответ — на русском, один абзац о результате + файл.
