ДОПОЛНЕНИЕ К ТЕХНИЧЕСКОМУ ЗАДАНИЮ CLAUDE

MANDALA ANALYTICS PREMIUM — TELEGRAM STARS SUBSCRIPTION

1. Цель

Реализовать платный доступ к разделу Mandala Analytics через ежемесячную подписку Telegram Stars.

Утверждённая бизнес-модель:

* Название продукта: Mandala Analytics Premium.
* Стоимость: 150 Telegram Stars.
* Период подписки: 30 дней.
* Автопродление: включено.
* Способ оплаты: Telegram Stars (XTR).
* Платёжная инфраструктура: существующий Telegram-бот Mandala.
* Доступ к аналитике: исключительно при наличии действующей Premium-подписки.

Не использовать Tribute, USDT, TON или банковские карты в качестве способа оплаты этой цифровой функции внутри Telegram Mini App.

Все платежи должны проходить через официальную систему Telegram Stars.

2. Логика доступа

Раздел Analytics должен существовать в интерфейсе приложения, но для пользователей без Premium-подписки показывать экран блокировки.

Экран должен содержать:

* Название Mandala Analytics Premium.
* Красивый предварительный обзор доступных возможностей.
* Примеры графиков и статистики.
* Календарь активности.
* Прогноз достижения целей.
* Success Score.
* Цену: 150 Stars / 30 дней.
* Кнопку «Подключить Premium».

После успешной оплаты сервер автоматически открывает доступ.

Проверка доступа должна выполняться на сервере при каждом запросе аналитических данных.

Запрещено доверять клиентскому состоянию, localStorage, Telegram WebApp-интерфейсу или переданному клиентом признаку isPremium.

3. Интеграция Telegram Stars

Использовать официальный Telegram Bot API.

Параметры подписки:

* currency = XTR
* amount = 150
* subscription_period = 2592000 секунд
* recurring = true, если требуется соответствующий параметр используемого метода

Перед реализацией проверь актуальную версию Telegram Bot API и правильную последовательность методов для создания invoice link и оплаты подписки.

Если Mini App запускает оплату из интерфейса приложения, использовать официальный механизм открытия Telegram invoice.

Не создавать собственную имитацию платёжного окна.

4. Обработка платежей

Реализовать полный цикл:

1. Пользователь нажимает «Подключить Premium».
2. Backend создаёт уникальный платёжный заказ.
3. Бот формирует Telegram Stars invoice.
4. Пользователь подтверждает оплату.
5. Бот обрабатывает pre_checkout_query.
6. После оплаты Telegram отправляет successful_payment.
7. Backend проверяет подлинность события и соответствие заказу.
8. Backend сохраняет данные транзакции.
9. Подписка активируется.
10. Пользователь получает доступ к Analytics.

ВАЖНО:

Никогда не активировать Premium после одного только pre_checkout_query.

Доступ выдаётся только после получения и успешной проверки подтверждённого платежа.

Сохранять:

* обновить дату окончания подписки;
* не создавать вторую независимую подписку;
* не начислять лишние 30 дней из-за повторной доставки одного события.

Использовать официальные поля Telegram, включая:

* is_recurring;
* is_first_recurring;
* subscription_expiration_date;
* telegram_payment_charge_id.

* после окончания периода автоматически закрыть доступ;
* сохранить все данные и историю аналитики пользователя.

Не удалять историю платежей и не удалять пользовательскую аналитику после отмены.

7. Недостаток Stars и неудачное продление

SUCCESS SCORE — оценка перспектив достижения цели.

Показывать процентный показатель от 0 до 100%.

Однако важно: не выдавать произвольную цифру за научно подтверждённую вероятность успеха.

Нужно разработать прозрачную модель оценки на основе реальной активности пользователя.

Предлагаемые составляющие:

* Регулярность активности — 30%.
* Темп выполнения задач — 30%.
* Текущий прогресс — 25%.
* Соблюдение сроков — 15%, если пользователь указал сроки.

Если сроки не заданы, модель должна автоматически нормализовать веса остальных показателей.

Дополнительные условия:

* При недостаточном количестве данных отображать «Недостаточно данных для прогноза».
* Не присваивать 100% пользователю только потому, что он выполнил много задач.
* Учитывать динамику активности, а не только общее количество посещений.
* Не считать простое открытие приложения полноценным прогрессом.
* Использовать выполнение задач как более значимый сигнал.
* Не повышать прогноз искусственно из-за частого открытия приложения без реальных действий.

Рядом с процентом обязательно показывать объяснение:

«Твоя текущая активность оценивается как высокая. Ты регулярно выполняешь задачи и сохраняешь положительную динамику».

Либо:

«Твоя активность снизилась. При текущем темпе продвижение к цели может занять больше времени».

Если имеются сроки и история выполнения, можно дополнительно показывать прогнозируемую дату достижения цели.

Название и описание показателя должны объяснять, что это аналитическая оценка текущего темпа, а не гарантированная вероятность жизненного успеха.
